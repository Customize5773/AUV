# SAUVC bridge lifecycle

Workspace-local executable for the YAML configurations generated by `sauvc_sim` launch. Topic names, message factories and QoS remain provided by the installed `ros_gz_bridge` library. Positional topic CLI syntax is outside this executable's scope.

On SIGINT/SIGTERM the handler only sets a lock-free stop flag. After executor work ends, the bridge cancels its heartbeat and releases handles, services and Gazebo node before destroying the ROS node and calling `rclcpp::shutdown()`. This explicitly breaks the Humble endpoint-to-owner reference cycles before middleware teardown.

Motivation and upstream fixes: [ownership issue #951](https://github.com/gazebosim/ros_gz/issues/951), [#952](https://github.com/gazebosim/ros_gz/pull/952), and [explicit shutdown #977](https://github.com/gazebosim/ros_gz/pull/977). The local crash was in Fast DDS publisher destruction; this is a workspace mitigation using the Humble SDK, not a replacement of global ROS packages or a claim to diagnose every historical shutdown failure.

`bridge_lifetime` checks actual String conversion in all three directions with an external Gazebo publisher and requires the bridge's weak owner reference to expire before ROS shutdown. The external publisher matters: the installed bridge deliberately ignores in-process Gazebo messages. The test also checks repeated endpoint release.

Build with the existing workspace command `bash tools/ros.sh build --symlink-install`. Native tests can run through the wrapper:

```bash
bash tools/ros.sh python -c 'import subprocess; subprocess.run(["ctest","--test-dir","build/sauvc_bridge","--output-on-failure"],check=True)'
```

The Ubuntu 24.04 host uses the existing `.native-deps/protobuf-3.12` fallback with Fortress's Protobuf 23 and YAML-CPP 0.7 ABI. Normal Humble/Ubuntu 22.04 builds use their installed SDK dependencies. Protected Humble endpoint fields are used intentionally; rerun the build and lifecycle tests when upgrading ROS/Gazebo. Simulation acceptance and the original failed run are recorded in [report 64](../../../plan/64-konsistensi-dan-benchmark-setelah-collision.md).
